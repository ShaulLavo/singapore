This page builds a TypeScript editor in six steps. It starts as plain text and ends with syntax colours, line numbers, search, type errors from a TypeScript language service in a worker, and a minimap. Every step shows the whole file so far, and below it an editor running exactly that file.

## Before you start

You need a Vite project and a container with a height, as in the [Quick start](/docs/start-here/quick-start/). Install the packages this page uses:

```sh
npm install @singapore-editor/core @singapore-editor/tree-sitter @singapore-editor/tree-sitter-languages @singapore-editor/gutters @singapore-editor/find @singapore-editor/typescript-lsp @singapore-editor/minimap
```

The editor opens a small TypeScript file. Save it as `sample.ts` next to your code. It holds two files: `main.ts`, which you edit, and `math.ts`, which `main.ts` imports.

<Code code={sample.replace(/\n$/, '')} lang='ts' />

## 1. Mount an editor

Create an `Editor` in the container and open `main.ts`. The document id is a path because the TypeScript step later resolves imports from it.

<PlaygroundStep step='1-editor' source={step1} label='Step 1: plain editor' />

The text is plain. You can select, type and undo, but nothing knows it is TypeScript yet.

## 2. Set a theme

A theme is a plain object. Set the background and text colours, and `type: 'dark'` so everything the theme leaves out gets dark defaults: the syntax colours in step 3 and the hover popup in step 5. To reuse a VS Code theme instead, convert it with `editorThemeFromVscodeTheme` from `@singapore-editor/core/shiki`.

<PlaygroundStep step='2-theme' source={step2} label='Step 2: themed editor' />

## 3. Add syntax colours

The tree-sitter plugin parses the document in a worker and colours it. `TREE_SITTER_LANGUAGE_CONTRIBUTIONS` registers the bundled grammars, and the TypeScript grammar downloads the first time a TypeScript document opens.

<PlaygroundStep step='3-syntax' source={step3} label='Step 3: syntax colours' />

The text appears at once and the colours arrive a moment later, after the worker parses the file.

## 4. Add line numbers and search

Line numbers and search are two more plugins, each with its own stylesheet.

<PlaygroundStep step='4-gutter-find' source={step4} label='Step 4: line numbers and search' />

Click into the editor and press Ctrl+F, or Cmd+F on a Mac, to search the file.

## 5. Add the TypeScript language service

`createTypeScriptLspPlugin` runs TypeScript in a worker inside the page, with no server. `setWorkspaceFiles` gives it the files the document imports, so `./math` resolves.

<PlaygroundStep step='5-typescript' source={step5} label='Step 5: TypeScript language service' />

The worker downloads TypeScript and its standard library on first use, so diagnostics appear a few seconds after the text. Then try it:

- Line 4 is underlined, because `twice` takes a number. Change `'two'` to `2` and the error goes away.
- Hover over `twice` to see its type.
- Type `orders[0].` on a new line to get completions.

## 6. Add a minimap

The minimap draws the whole document beside the text. Drag it to scroll.

<PlaygroundStep step='6-minimap' source={step6} label='Step 6: minimap' />

That is the finished playground. Keep the returned editor and call `editor.dispose()` when the view closes, which also stops its workers.
